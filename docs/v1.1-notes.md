# v1.1 implementation notes

Interpretations recorded outside the PRD, which the owner has not been asked to
edit. The PRD v1 non-goals for sound, a watchface, an app glance and lifetime stats were lifted
by the owner for v1.1. Nothing here is verified on a physical watch unless stated.

## Fidelity quick wins (item 6)

- **Game-over idle return.** On the game-over screen a single 5-minute `AppTimer`
  (`PGW_GAME_OVER_IDLE_MS` in `tuning.h`) returns to the clock. Any movement press
  restarts it; Select / Back / hold leave the screen anyway. It is cancelled by
  focus loss, page changes and exit, and re-armed on focus return, so it never
  runs while the app is hidden, paused or on another page. It is not the original's
  exact ~5 minutes, only an adaptation.
- **Hold Select on the clock shows the best score.** Select is now a raw click on
  every page: pressing it on the clock immediately shows Game A's best with the
  HI segment (`scene_best`, score modulo 1000 like the game display); passing the
  existing 600 ms long-press threshold switches to Game B's best; release starts
  the mode shown. Tap = A and hold = B are unchanged. Other pages still act on
  release, and the long press on game over still starts the other mode. A hold is
  abandoned (release ignored) if an alarm starts, focus is lost, or another page
  opens meanwhile, so a late release never starts a game by surprise. An alarm that is
  already ringing keeps the old behaviour (the first press dismisses it).
  The Game-over screen keeps its immediate Select restart: the original
  hold-to-show applied to its Game button, but a game-over preview would add a
  press before every replay.
- Verified on the emulator (landscape): hold preview for B and release-to-start,
  menu and stats pages. Timings of the real button feel are unverified.

## App Glance (item 4)

`glance_text` (pure, host-tested) builds "Best A 214 / B 187", appending
" - 07:00" (or " - 7:00 AM" in 12-hour style) while the alarm is on, and "No scores
yet" before the first score. It uses ASCII only (no `{`: the glance parses
templates). `window_unload` calls `app_glance_reload` once, after flushing scores:
no timers and no background work. The first update appears after the first exit.
The launcher may truncate the longer alarm form; the emulator showed the
score-only text in full ("Best A 1 / B 0").

## Sound (item 1)

- Setting **Sound** (default On), after Vibrate. The settings record is now version
  **5** (bit 7). The brief called this "v4", but v4 already existed (retained
  button position); v1–v4 records decode unchanged with Sound On, and a set bit 7 in
  v1–v4 is still rejected. Tests exercise all 256 flag values for versions 1–5.
- Cues are plain tables in `feedback.c` (`feedback_sound_cue` / `feedback_sound_notes`),
  played as square-wave notes through `speaker_play_notes` at volume 60 by
  `feedback_service_play`. Notes are original motifs:

  | Cue | MIDI notes (ms) |
  |---|---|
  | Catch | 91 (45) |
  | Drop / MISS (also Brutus hit) | 72 (150) |
  | 200/500 bonus | 88 (70), 95 (110) |
  | Game over | 79, 76 (110 each), 72 (220) |
  | New best at game over | 84, 88, 91 (80 each), 96 (200) |
  | Alarm ring | four 70 ms beeps on 96 separated by 60 ms rests |

- Priority per tick: game over (ascending if a record) > bonus > drop/MISS > catch,
  so the third miss and game over give only the game-over cue. Launches and new-best
  catches are silent.
- Gates: the Sound setting, `speaker_is_muted()` and `quiet_time_is_active()` (the
  same Quiet Time test as vibration), and the game must be running (not paused,
  hidden, or behind a full-screen alarm). A new cue stops the previous one.
  `speaker_stop` runs on pause, focus loss, restart (feedback reset), leaving the
  game page, alarm dismissal, turning Sound Off and exit.
- Alarm: the ring beeps with the vibration pulses (on ring start and every other
  second while idle). An in-game (passive) alarm stays silent like its vibration.
  **Test alarm** also beeps.
- Toggling Sound On plays the catch beep as a preview.
- Unverified: loudness, pitch response of the PT2 speaker and how the cues feel;
  the volume (60) and pitches are guesses to tune on the watch. The emulator does
  not play audio.

## Lifetime stats (item 5)

- Record key **4**: version 1, eight little-endian u32 fields, FNV-1a checksum
  (37 bytes): games A/B, catches, drops, Brutus hits, bonuses, best streak,
  active play seconds. A record whose best streak exceeds its catches is rejected.
  Totals saturate.
- Counting is from per-tick game events (`stats_note_events`): a catch; a drop;
  a MISS without a drop is a Brutus hit; a bonus per 200/500 clear. At most one
  food lands per tick and a hit ends its tick, so the event mask is unambiguous;
  the host test cross-checks the totals against the engine's own counters over 120
  imperfect games.
- **Best run** is catches in a row without a MISS (the in-game red can, not a first
  drop). The run restarts each game and ends at any MISS. A first drop (half can)
  does not break it.
- **Games played** counts a round once it has scored or ended (game over). Quitting
  before the first point without game over does not count.
- **Play time** is the time the step/recovery timers actually ran, taken from the
  timer intervals themselves (and the partial interval at a pause). Menus, pauses,
  hidden time and game-over screens are excluded; MISS recovery counts.
- Saved with the scores (pause, game over, focus loss, window unload) rather
  than per catch. A failed stats write shows the usual "Save failed" notice.
- UI: **Menu → Stats** (after High scores), two 4-row pages browsed like Help.
  Select on page 2 opens "Reset stats?" (Keep stats is the default); resetting
  stats never touches high scores and the high-score reset never touches stats.
- `ViewPanel.rows` grew from 6 to 8 because Settings has 7 rows in Horizontal mode.

## Companion watchface (item 2): Popeye G&W Clock

Identity: display name `Popeye G&W Clock`, slug `popeye-gw-clock`, version 1.0.0,
its own UUID `9f808f24-978d-4e7d-9af1-16bd31e4b8c5`, `"watchface": true`, Emery only.
It is a separate Pebble project in `watchface/` that installs beside the game; it
is not part of the game's PBW and does not touch the game's persistent data.

### Build, test, install

```sh
cd watchface
rm -rf build && TERM=xterm pebble build        # check exit status and 'build' finished
./test.sh && ./test.sh --sanitize               # host tests of the face scene logic
pebble install --emulator emery build/popeye-gw-clock.pbw
pebble install --cloudpebble build/popeye-gw-clock.pbw   # physical Pebble Time 2
```

The bundle is `watchface/build/popeye-gw-clock.pbw`. The build checks the linked
image against the same 61,440-byte budget (`tools/check_app_size.py` is reused).
The root `./tools/test.sh` and the root build do not include the watchface;
`watchface/test.sh` is separate (it is not wired into CI).

### What it shows

The same LCD clock scene as the game's clock page: backdrop with ghost outlines,
four digits, colon, Olive on her ledge, Popeye in the centre pose and Brutus idle.
AM/PM is lit from the 12/24h watch preference, read on every minute change. The
colon is steady (the game's blinking colon belongs to its second-by-second
attract mode). There is no alarm bell, settings, orientation switch or buttons:
the face is portrait only and every button keeps its system behaviour.

### Reuse without copying

waf accepts sources and include paths outside the project directory, so
`watchface/wscript` compiles `../src/c/scene.c`, `clock.c` and `game.c`
(`game.c` only for `game_lane_pose`; the linker drops the rest) and adds
`../src/c` to the include path. `segments.h` (generated) is included from there.
The SDK insists on a `resources/` directory inside the project, so
`watchface/resources/` holds only a note, and `package.json` points the two media
entries at `../../resources/images/backdrop-ghosts.png` and `segments.png`.
No symlinks and no duplicated source or art; `watchface/test.sh` fails if a
copy of a shared file appears under `watchface/`.

New code is `watchface/src/c/face.c` (pure scene selection) and `main.c`
(window, bitmaps, minute tick, demo timers).

### Food demonstration: once per minute, not on wrist flick

The game's attract cycle is six 2-second beats (idle, throw, three flights, catch)
derived from the wall-clock seconds. For the face:

- A `MINUTE_UNIT` tick is the only permanent subscription. Between minutes the
  face is static: no timers, no second ticks, no accelerometer.
- On each minute change the demo runs beats 1 to 5 (throw to catch, about 10 s)
  with a chain of one-shot `AppTimer`s of 2 s, then returns to the static face.
  Beat 0 (idle) is skipped so the throw starts the moment the minute changes.
  `face_scene` feeds `clock_scene` an even second matching the beat, so a frame
  is identical to what the game's attract clock draws at that second, and the
  food lane follows the minute (minute mod 4) as in the game.
- The demo is skipped when the face is covered (focus service), Quiet Time is
  active, or the battery is at 20 % or below and not charging. The time and AM/PM
  always update.
- No vibration, no sound.

Wrist-flick (`accel_tap_service`) was considered and rejected: it keeps the
accelerometer sampling for the whole time the face is on screen and fires on
unintended movement; the once-a-minute demo costs about five timer wake-ups a
minute and nothing else. Adding it later is a small change in `main.c`.

### Size

`watchface/build/emery/pebble-app.elf`: `.text + .data + .bss` is 3,294 + 8 + 364 =
**3,666 bytes** of the 61,440-byte budget; unused `game.c` code is removed by the
linker. Resources 9,523 bytes (two images; the sprite sheet is 1-bit palette).
